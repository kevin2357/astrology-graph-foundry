# ADR-0002: Separate Chart, Calculation, Artifact, and Projection Identity

- **Status:** Accepted
- **Date:** 2026-08-05
- **Applies from:** Astrology Graph Foundry 0.6.0
- **Decision owner:** Astrology Graph Foundry for source/calculation contracts; orchestration and SPC retain their own boundaries

## Context

Durable caching and lineage require several superficially similar hashes and IDs. Collapsing them would make renames look like astronomical changes, make identical geometry merge distinct subjects, confuse regenerated bytes with semantic equality, or leak downstream interpretation into canonical source identity.

Historical cached packages also cannot prove which astronomy runtime and data produced their original coordinates. AGF must not manufacture missing provenance during replay.

## Decision

AGF keeps these dimensions distinct:

- `source_chart_id`: caller-owned canonical chart lineage;
- `source_input.sha256`: normalized geometry-affecting birth facts plus normalization-policy version;
- `configuration_sha256`: versioned calculation profile, invocation settings, provider behavior, and ephemeris-data inventory;
- `sensor_instance_id`: one technique or observation instance;
- exact output artifact SHA-256: orchestration-owned hash of persisted bytes; and
- projection context and projection identity: downstream-owned by SPC/application policy.

Display name, location label, and `source_chart_id` do not enter the geometry input hash. Machine filesystem paths do not enter configuration identity. AGF records ephemeris data by content inventory rather than path.

AGF does not embed a final artifact hash in its own artifact. The persistence owner hashes the exact returned bytes and records that digest with the dependency lock. Cached replay reports incomplete historical provenance rather than inferring the original live runtime.

## Alternatives rejected

- **One universal chart hash:** conflates lineage, geometry, configuration, bytes, and downstream context.
- **Self-embedded output hash:** creates a recursive envelope and still may not equal persisted bytes.
- **Hash display metadata with geometry:** turns harmless descriptive edits into calculation changes.
- **Treat paths as data provenance:** paths are machine-local and say nothing reliable about file content.
- **Backfill cached runtime claims from the current environment:** misrepresents historical calculation ancestry.

## Consequences

Cache keys combine the dimensions appropriate to their layer. Repeated calculations may have equal input/configuration hashes while differing in operational `metadata.created_at` and exact bytes. The API or other persistence owner must retain the full artifact and byte hash. Downstream projection never alters source identity.
