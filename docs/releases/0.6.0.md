# Astrology Graph Foundry 0.6.0

**Status:** published and download-verified

AGF 0.6.0 establishes an explicit production chart-identity boundary and a qualified immutable packaging baseline for AstroWoof and other consumers.

The [release retrospective](../history/foundry-development/Foundry%200.6.0%20Identity%20and%20Release%20Retrospective.md) summarizes surprises and reusable lessons; the [ADRs](../decisions/README.md) preserve the architectural rationale.

## Highlights

- Callers can supply opaque, stable `source_chart_id` values through supported live Natal generation.
- Canonical object and relationship identity remains stable across display-name changes when explicit chart identity is unchanged.
- Canonical identity migration is reference-complete and idempotent.
- Calculation provenance now includes versioned normalization and calculation profiles, normalized source-input hashing, canonical configuration hashing, and explicit provider/runtime observations.
- Installed runtime resources have a deterministic hashed manifest.
- Saved-package and projection modes work without pyswisseph.
- The qualified live profile is CPython 3.11 on glibc Linux x86-64, exact pyswisseph 2.10.3.2, explicit Moshier mode, no external ephemeris files, and optional file-backed points disabled.
- Installed AGF 0.6.0 projects successfully through the exact SPC 0.10.0 wheel while preserving explicit chart identity.

## Compatibility notes

The explicit identity input is additive, but it is a material public contract; the package therefore advances from 0.5.x to 0.6.0. The deterministic name-derived fallback remains for compatibility and is not suitable for durable production joins.

Library metadata permits SPC `>=0.10.0,<0.11`; production deployment must pin the exact SPC 0.10.0 wheel and hash. Live-provider metadata permits pyswisseph `>=2.10,<2.11`; the only live combination qualified by this release is the narrower profile above.

No sdist is published. Additional Python/platform combinations, Swiss/JPL file-backed modes, Chiron, asteroids, fixed stars, and external ephemeris data remain unqualified.

## Operational gate

Technical qualification does not authorize public Swiss Ephemeris service activation. AstroWoof must document an approved AGPL-compliance or Swiss Ephemeris Professional License path before public activation. This note is an engineering release constraint, not legal advice.
